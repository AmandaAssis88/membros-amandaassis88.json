Última aula da trilha: duas ferramentas de pensamento. A primeira é a **recursão**, um jeito elegante de resolver problemas que se repetem dentro de si mesmos. A segunda é um **método** para encarar qualquer problema novo, seja num exercício, numa entrevista ou no trabalho.

<Chute pergunta="Uma função pode chamar ela mesma?">

Pode, e isso se chama **recursão**. O truque é que cada chamada resolve um pedaço **menor** do problema, até chegar num caso tão pequeno que a resposta é óbvia. Sem esse caso pequeno, a função chamaria a si mesma para sempre.

</Chute>

## Recursão: o problema dentro do problema

<Nota tipo="analogia" titulo="Pensa assim: as bonecas russas">

Para contar quantas bonecas tem dentro de uma matriosca, você abre a de fora e... tem outra matriosca, igual, só que menor. Você repete o mesmo processo com ela. Até abrir uma que **não tem nada dentro**: essa é a resposta trivial. Aí você volta somando: 1 + 1 + 1...

</Nota>

Toda função recursiva tem duas partes:

1. **Caso base**: o caso pequeno com resposta direta. Ele para a recursão.
2. **Passo recursivo**: resolve o problema usando a **mesma função** num pedaço menor.

### Exemplo: fatorial

O fatorial de 5 (escrito 5!) é `5 × 4 × 3 × 2 × 1 = 120`. Repare que `5! = 5 × 4!`, e `4! = 4 × 3!`... É um problema dentro do problema.

<Abas>
<Aba rotulo="Python">

```python
def fatorial(n):
    if n <= 1:
        return 1
    return n * fatorial(n - 1)


print(fatorial(5))
print(fatorial(10))
```

</Aba>
<Aba rotulo="Java">

```java
public class Main {
    static long fatorial(int n) {
        if (n <= 1) return 1;
        return n * fatorial(n - 1);
    }

    public static void main(String[] args) {
        System.out.println(fatorial(5));
        System.out.println(fatorial(10));
    }
}
```

</Aba>
</Abas>

```saida
120
3628800
```

### Como o computador executa isso: a pilha de chamadas

Lembra da pilha da aula 4? Cada chamada fica **esperando** a de baixo terminar, empilhada:

```texto
fatorial(5) espera  5 × fatorial(4)
  fatorial(4) espera  4 × fatorial(3)
    fatorial(3) espera  3 × fatorial(2)
      fatorial(2) espera  2 × fatorial(1)
        fatorial(1) → 1          ← caso base: começa a voltar
      fatorial(2) → 2 × 1 = 2
    fatorial(3) → 3 × 2 = 6
  fatorial(4) → 4 × 6 = 24
fatorial(5) → 5 × 24 = 120
```

<Nota tipo="cuidado" titulo="Sem caso base, a pilha estoura">

Se você esquecer o `if n <= 1`, a função se chama para sempre, a pilha de chamadas enche e o programa quebra: `RecursionError` em Python, `StackOverflowError` em Java. É daí que vem o nome do site **Stack Overflow**.

</Nota>

### Quando recursão brilha

Para fatorial, um `for` resolve igual. A recursão brilha em problemas que são **naturalmente aninhados**:

- **Pastas dentro de pastas**: somar o tamanho de uma pasta é somar os arquivos dela mais o tamanho de cada subpasta (que é... o mesmo problema).
- **Árvores**: menus com submenus, comentários com respostas, a árvore de elementos de uma página web.
- **Dividir para conquistar**: o Merge Sort da aula 3 é recursivo.

```python
cardapio = {
    "Bebidas": {
        "Quentes": ["café", "cappuccino", "chá"],
        "Geladas": ["suco", "chá gelado"],
    },
    "Comidas": ["pão de queijo", "bolo"],
}


def contar_itens(secao):
    if isinstance(secao, list):
        return len(secao)
    return sum(contar_itens(sub) for sub in secao.values())


print(contar_itens(cardapio))
```

```saida
7
```

`contar_itens` não sabe quantos níveis o cardápio tem, e não precisa saber: se for uma lista, conta (caso base); se for um grupo, soma o que cada subgrupo tem (passo recursivo).

<Explique pergunta="Quais são as duas partes obrigatórias de uma função recursiva, e o que acontece se faltar uma delas?">

O caso base, que dá a resposta direta para o menor problema e faz a recursão parar, e o passo recursivo, que chama a mesma função com um problema menor. Sem caso base, a função se chama para sempre e a pilha de chamadas estoura. Sem diminuir o problema no passo recursivo, também nunca chega ao caso base.

</Explique>

<Tarefa titulo="Entrevista simulada: o primeiro repetido">

Problema: dada uma lista de números de comanda, devolva o **primeiro número que aparece repetido** (o primeiro cuja segunda ocorrência vem antes de todos os outros repetidos). Se nenhum se repetir, devolva `None`.

```texto
[42, 7, 19, 7, 42, 3]  → 7     (o 7 se repete antes do 42)
[1, 2, 3]              → None
[]                     → None
```

Siga o método: escreva a **força bruta**, diga o Big O, depois **otimize** e diga o novo Big O.

<Dica>

Força bruta: para cada posição, olhe para trás procurando o mesmo número. Para otimizar, pergunte-se: "estou procurando algo dentro de um laço?". Um conjunto dos números já vistos responde "já apareceu?" em O(1).

</Dica>

<Resposta>

```python
def primeiro_repetido_bruto(lista):
    for i in range(len(lista)):
        for j in range(i):
            if lista[j] == lista[i]:
                return lista[i]
    return None


def primeiro_repetido(lista):
    vistos = set()
    for n in lista:
        if n in vistos:
            return n
        vistos.add(n)
    return None


for teste in [[42, 7, 19, 7, 42, 3], [1, 2, 3], []]:
    print(primeiro_repetido_bruto(teste), primeiro_repetido(teste))
```

```saida
7 7
None None
None None
```

- Força bruta: dois laços, **O(n²)** de tempo e O(1) de memória.
- Otimizada: uma passada com conjunto, **O(n)** de tempo e O(n) de memória. Trocamos memória por tempo, a troca mais comum dos algoritmos.

</Resposta>

</Tarefa>
